# Правила для агентов — краткая шпаргалка

Полные правила: [`.agents`](../.agents).

## Кто где работает

В текущей ветке по прямому разрешению владельца совмещены роли:
**Участник 1** (`core/`, `submission/`) и **Участник 3** (`tests/`).
Каталоги `backend/`, `frontend/`, `worker/` не создаются и не изменяются.

| Участник | Каталоги |
| --- | --- |
| Участник 1 | `core/`, `submission/` |
| Участник 2 | `backend/`, `frontend/`, `worker/` |
| Участник 3 | `tests/` (текущая ветка) |

Чужие каталоги не изменяются. Общие файлы (`README.md`, `pyproject.toml`,
`poetry.toml`, `.gitignore`, `.env.example`, `CHANGELOG.md`,
`docs/ARCHITECTURE.md`) — только по явной команде пользователя.

## Зависимости

Один Poetry-проект: `pyproject.toml` + `poetry.lock`. Существующие
зависимости заморожены — версии не меняются, новые пакеты добавляются только
по явной команде пользователя и с записью в `CHANGELOG.md`.

```bash
poetry install              # установка окружения
poetry run python -m compileall core submission
poetry run pytest           # прогон тестов
```

## Секреты

`.env` не читается агентом. Образец переменных — `.env.example`. Значения
ключей не попадают в код, логи, тесты и сообщения коммитов.

## Коммиты

Один коммит на логическую единицу, не реже раза в 30–60 минут.
Формат: `<участник>: <область> — <что сделано>`.

Перед коммитом:

```bash
git status
git diff --cached --stat
```

## Универсальность

Рабочий RAG не подстраивается под Golden Dataset: запрещены ветвления по ID,
эталонные ответы, жёстко заданные юридические факты и специальные пороги для
известных примеров. Поиск, редакции, полнота, вычисления, отказ и исправление
опираются только на вопрос, структуру документов и проверенные доказательства.
Любое новое правило проверяется на изменённых сущностях, датах, суммах,
формулировках и порядке источников.
## Golden quality gate

Каждый Golden-прогон обязан завершаться автоматическим Python-расчётом доступных метрик качества.
Отчёт без вычислимых метрик неполон; `N/A` допускается только с конкретной причиной и не заменяет отсутствующие данные нулём.
Метрики пересчитываются из сохранённых трасс без повторных обращений к моделям, исторические результаты не перезаписываются.
Экономия токенов Codex относится только к Codex и не является основанием искусственно ограничивать DeepSeek.
